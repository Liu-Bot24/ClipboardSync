# ClipboardSync 原生 macOS 客户端

用 Swift（AppKit + SwiftUI）写的菜单栏客户端，用来替代 Electron 版 Mac 客户端。它直接使用现有 Hub 协议，不需要改 Hub，可以和 Windows 上的 Electron 客户端同时使用。

> **状态：未在 Mac 上编译运行过。** 代码在 Windows 上编写。平台无关的核心库（协议、策略、同步逻辑）已在 Linux 的 Swift 5.10 中编译，76 个单元测试全部通过；AppKit/SwiftUI 部分只做过语法解析，第一次构建请按下面的步骤在 Mac 上验证。未验证项见文末。

## 要求

- macOS 13 或更高版本，优先 Apple Silicon
- Xcode 15 或更高版本，或带 Swift 5.9+ 的 Command Line Tools（`xcode-select --install`）
- 无第三方依赖

## 构建与运行

```bash
cd mac-native
swift test                    # 协议、策略、同步逻辑的单元测试
Scripts/build-app.sh          # 生成 build/ClipboardSync.app（arm64，ad-hoc 签名）
open build/ClipboardSync.app
```

- 通用二进制：`ARCHS="arm64 x86_64" Scripts/build-app.sh`
- 长期使用请先把 App 移到 `/Applications` 再打开，开机启动会登记 App 当前所在的位置。
- 不要用 `swift run` 运行裸二进制：没有 App 包时，开机启动、本地网络权限归属和辅助功能权限都不对。
- 也可以用 Xcode 打开 `Package.swift` 编辑和调试，但发布请用上面的脚本，因为它会写入 `Info.plist`（菜单栏模式、本地网络说明、Bundle ID）。

## 签名

脚本默认使用 ad-hoc 签名（`-`）。ad-hoc 签名每次重新构建都会变化，macOS 会把它当成新的 App：辅助功能权限需要重新勾选，钥匙串可能再次询问，本地网络权限可能再次弹窗。

建议使用固定证书，免费 Apple ID 即可：

1. Xcode › Settings › Accounts 登录 Apple ID，点 Manage Certificates 创建 “Apple Development” 证书。
2. 查看证书名：
   ```bash
   security find-identity -v -p codesigning
   ```
3. 用该证书构建：
   ```bash
   SIGN_IDENTITY="Apple Development: 你的名字 (TEAMID)" Scripts/build-app.sh
   ```

如果使用 “Developer ID Application” 证书，脚本会开启 hardened runtime 并加时间戳，之后可用 `xcrun notarytool` 公证；只在自己的电脑上使用时不需要公证。

## 首次启动

- 设置保存在 `~/Library/Application Support/dev.liuqi.clipboardsync.mac/config.json`，Hub 令牌保存在登录钥匙串（服务名 `dev.liuqi.clipboardsync.mac`）。
- 首次启动时，如果发现 Electron 版设置（`~/Library/Application Support/Clipboard Sync/config.json`），会导入 Hub 地址、令牌、设备名、语言、暂停和收发规则。Electron 版通过本地代理 `127.0.0.1:18787` 连接时，会改用代理配置里的真实 Hub 地址。
- 原生版使用新的设备 ID，因此和 Electron 版同时运行也不会在 Hub 上互相挤掉。其他设备上按 IP 设置的收发规则会自动应用到新 ID。
- 切换前请退出 Electron 版，并关闭它的“开机启动”或删除它，避免两个客户端同时同步。
- 未设置服务器时会自动打开“收发设置”窗口。

## 权限

| 权限 | 何时需要 | 位置 |
| --- | --- | --- |
| 本地网络 | 第一次连接局域网 Hub 时系统弹窗（macOS 15 起） | 系统设置 › 隐私与安全性 › 本地网络 |
| 辅助功能 | 点击历史后自动粘贴（发送 Cmd+V） | 系统设置 › 隐私与安全性 › 辅助功能 |
| 登录项 | 开机启动 | 系统设置 › 通用 › 登录项 |

没有辅助功能权限时，点击历史只写入剪贴板，并提示需要权限。用 ad-hoc 签名重新构建后，如果自动粘贴失效，请在辅助功能列表里删除旧的 Clipboard Sync 再重新添加，或执行：

```bash
tccutil reset Accessibility dev.liuqi.clipboardsync.mac
```

## 局域网连接，不再需要本地代理

Electron 版在 macOS 上需要一个 C 写的本地代理（`127.0.0.1:18787`）转发到 NAS，因为 Electron 的网络请求在本地网络隐私限制下不能稳定访问局域网地址。原生版是一个带 `NSLocalNetworkUsageDescription` 的普通 App，由 App 自己发起连接，按设计会正常弹出本地网络授权，所以直接连接 Hub。连接时不走系统 HTTP 代理，和 Electron 版的 `ws` 行为一致。

在 Mac 上这样确认：

1. 服务器填 NAS 的局域网地址，例如 `http://192.168.1.10:8787`，点保存。
2. 系统弹出本地网络授权时选择允许。
3. 菜单栏状态显示“已连接”，图标不再变灰；Windows 客户端的设备列表里出现这台 Mac。
4. 在 Mac 复制文本，Windows 能粘贴；反过来也一样。

如果状态一直是“已断开”或“连接错误”，并提示 `No route to host` 或网络不可用，请检查“本地网络”里 Clipboard Sync 的开关。如果 Hub 地址用的是域名，并且该域名在局域网 DNS（例如 Surge）里解析成 `198.18.*` 假 IP，请改用 NAS 的真实 IP，或在 Surge 中为该域名配置 `always-real-ip`。

## 功能

- 文本和 PNG 图片双向同步；收到 JPEG/WebP 时转换成 PNG 写入剪贴板。
- 用 `NSPasteboard.changeCount` 检测本机复制（每 0.3 秒读一次计数），只在计数变化时读取一次内容，图片不会被反复解码。
- 用 `NSWorkspace` 激活通知记录前台应用，不轮询进程；点击历史时粘贴到之前的前台应用。
- 菜单栏：状态、收发设置、历史（主窗口和最近条目，点击直接粘贴）、暂停发送、暂停接收、开机启动（SMAppService）、语言、退出。
- 收发设置窗口：服务器和可选令牌、按 IP 分组的设备列表（每组发送/接收开关，组内设备设置不一致时显示混合状态）。
- 历史窗口：缩略图、点击粘贴、右键复制或粘贴、清除全局历史（需点两次确认）、总在最前。窗口是不抢焦点的浮动面板，点击时输入焦点仍留在原来的应用里。
- 唤醒后和网络切换后立即重连；Hub 以 4000 关闭连接时约 30 秒后重试；30 秒心跳。
- 只有 Hub 确认了本机接收策略后才显示“已连接”。

### 与 Electron 版的差异

- 剪贴板同时有文字和图片时优先同步文字（Office、Pages 复制文字时会附带渲染图）。
- 带 `org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` 标记的内容（密码管理器）不会同步。
- Finder 里复制文件不会同步（Electron 版会把文件图标当作图片发送）。
- 暂停发送期间的复制在恢复后不会补发。
- 未确认的发送每 5 秒重试一次，最多 6 次。
- 复制来源识别和忽略规则只在 Windows 上有，Mac 版没有。

```
  Package.swift

  Scripts/build-app.sh            # 构建、打包、签名

  Tests/ClipboardSyncCoreTests/   # swift test
```

## 卸载

1. 菜单栏 › 退出，删除 `/Applications/ClipboardSync.app`。
2. 删除 `~/Library/Application Support/dev.liuqi.clipboardsync.mac/`。
3. 在“钥匙串访问”中删除 “Clipboard Sync Hub token”。
4. 在系统设置的登录项、辅助功能、本地网络中移除 Clipboard Sync。

## 未验证项

以下内容需要第一次在 Mac 上构建时确认：

- **AppKit/SwiftUI 部分能否编译**：这部分只做过语法解析，没有用 macOS SDK 做类型检查。最可能出问题的是 SDK 并发标注（`@MainActor`、`Sendable`）带来的告警或错误。
- **WebSocket**：`URLSessionWebSocketTask` 对自定义关闭码 4000 的报告、`Authorization: Bearer` 请求头在握手中是否保留、64 MiB 消息上限、服务器 ping 的自动 pong。
- **本地网络**：直连局域网 Hub 不需要本地代理这一点是按系统设计推断的，尚未在 macOS 15 上实测。
- **剪贴板**：写入后 `changeCount` 只变化一次的假设、延迟提供的 TIFF 数据、截图和各类 App 的图片类型。
- **自动粘贴**：不抢焦点的历史面板首次点击能否触发按钮和行、从菜单栏历史粘贴到前台应用、macOS 14 的协作激活（`yieldActivation`）。
- **其他**：开机启动登记、钥匙串读写、Electron 设置导入、App Nap 被阻止后的耗电、睡眠唤醒和网络切换后的重连、内存和磁盘占用的实际数值。
